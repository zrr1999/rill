# 全局模型配置与工作流模型类别

日期：2026-10-11。状态：实现与验收进行中。
源码基线：`fc934720a80d71b8d10cabacff315ffc38175078`。
本文保留原设计依据，并记录本次实现范围与验证进度；当前产品合同以源码和正式文档为准。

## 目标与已确认决定

全局设置是具体模型选择的唯一所有者。工作流描述任务、选择模型类别，运行时在启动时
将类别解析为具体模型配置。同一工作流不再拥有另一套供应商、模型或推理开关。

| 决定 | 来源与状态 |
| --- | --- |
| 智能文本模型启用推理，快速文本模型关闭推理 | 用户本轮提出的方向；作为两类文本模型的语义 |
| 工作流只能选择类别，不能指定具体模型 | 用户本轮明确要求 |
| ASR 只保留一个全局类别，不再区分快速和智能 ASR | 用户在 2026-10-11 的选项回复中明确选择 |
| 已有工作流中的具体模型统一迁移为类别，之后跟随全局设置 | 用户在 2026-10-11 的选项回复中明确选择 |

迁移选择允许旧工作流改为跟随全局模型，不意味着可以删除用户文件、改变任务提示词，
或扩大任何内容上传授权。

## 类别与配置归属

建议使用固定类别，不引入可由用户无限创建的模型 profile 和配置继承链。

| 类别 | 全局配置内容 | 工作流或调用方保留的内容 |
| --- | --- | --- |
| `intelligent` 智能文本 | 服务连接、具体模型、启用推理的策略 | 提示词、输入、输出、是否使用这一类别 |
| `fast` 快速文本 | 服务连接、具体模型、关闭推理的策略 | 提示词、输入、输出、是否使用这一类别 |
| `classifier` 分类/评分 | 支持的分类供应商、具体模型、凭据 | 候选项、评分标准，以及结果如何参与任务决策 |
| `asr` 语音识别 | 识别后端、具体模型、下载/启用/资源状态 | 识别语言、词库、字幕行为 |
| `tts` 语音合成 | 合成后端、具体模型、资源状态 | 要朗读的内容及兼容的声音、语言参数 |

用户随后授权直接支持 Jev / Cloudflare Clef。已核对 Workers AI 官方 Clef 与 Clef Flash 的输入、输出 schema，并实现 REST 适配和严格响应校验。

TTS 遵循同样的模型归属，避免仍从工作流绕过全局选择。Embedding、VAD 等内部模型
继续由各自能力和资源管理模块维护，不因此新增工作流选择项或通用配置平台。
统一所有权不要求把所有设置、模型下载和运行状态塞进一个大对象。

智能和快速是两个固定的文本能力入口；供应商、具体模型及推理策略在全局绑定中组合。
两个类别可以选同一个具体模型，前提是适配器能分别保证启用与关闭推理。
同一 API 连接可以复用凭据，但工作流不能引用连接、端点或 Key。
不支持某种推理策略时，配置验证应直接说明不支持，不能接受后忽略策略。

分类、评分和候选排序具有不同的输入输出合同。共享分类模型配置，不等于把它们
合成一个无类型的文本生成接口，也不在此次配置重构中新增通用分类流程节点。

## 工作流声明

以下语法已由 workflow v3 解析器支持：

```toml
[[process]]
id = "cleanup"
kind = "llm-rewrite"
model_role = "fast"
prompt = "修正语音识别中的错误，保留原意。"

[[process]]
id = "answer"
kind = "llm-answer"
model_role = "intelligent"
prompt = "根据输入回答问题。"
```

类别属于每个模型步骤，同一工作流可以先快速整理，再智能回答。步骤仍然定义
rewrite/answer 的任务语义；选择智能模型不会把 rewrite 变成回答请求。

只有一个 ASR 类别时，`recognize-speech` 已足以表达使用 ASR，不必再要求重复填写
`model_role = "asr"`。`speech.speak` 同理。条件分支、提示词、词库、输出顺序和
输出目标继续属于工作流。

新声明不允许出现具体模型和供应商字段。旧的 `local_model`、`provider_model`、
recognizer 选择、`speech.provider`、`speech.model` 只在导入迁移边界识别；
迁移后不进入可执行计划。开放字典也不能成为重新添加模型覆盖的入口。

## 运行边界

```text
工作流步骤的模型类别 + 当前全局配置
                 ↓ 准入时解析并检查能力
一次运行的模型配置快照
                 ↓ 按实际目的地执行隐私检查
已授权的运行计划 → 各模型适配器 → 现有顺序执行与回执
```

沿用现有 workflow compiler/coordinator，不建立第二套执行器。

1. 准入时只解析本次工作流需要的类别。未使用的模型未配置，不应阻止纯文本或纯 ASR 工作流。
2. 文本模型、ASR、TTS 等实际绑定进入同一运行拥有的快照；录音在开始采集时取得快照。
   后续步骤不再重新选择模型。全局修改应用于下一次运行。
3. 预览、就绪检查、云端确认和执行使用同一套类别解析规则，避免界面说明一种配置，
   请求实际发送到另一种目的地。授权身份包含实际连接和模型，而非仅包含类别名称。
4. 冻结模型不冻结权限。隐私撤销、凭据失效和模型禁用仍在调用边界检查；失败时停止
   对应调用，不在后台改用另一类别或另一个模型。
5. 保留已有业务失败语义，例如允许保留原文的整理失败、以及顺序输出的部分完成回执。
   模型选择规则不负责重新定义这些行为。
6. 运行历史显示实际执行的模型信息，不用今天的全局配置重建旧运行；凭据不写入回执。

## 迁移方案

推荐升级工作流格式版本，使新的模型归属成为明确合同。旧版本只经过单向转换，
转换结果进入新的执行路径；不保留旧的覆盖优先级。

| 旧内容 | 转换结果 |
| --- | --- |
| ASR recognizer、local/provider model 覆盖 | 单一 `asr` 类别，使用全局模型 |
| `llm-rewrite` 未声明类别 | 显式 `fast` |
| `llm-answer` 未声明类别 | 显式 `intelligent` |
| TTS provider/model 覆盖 | `tts` 全局绑定 |
| Jev 用途开关 | 保留用途和独立授权，模型归全局分类配置 |

保持 workflow/step ID、enabled 状态、提示词、语言、词库、分支和输出顺序。
用户已选择迁移后使用全局模型，因此迁移记录应清楚说明被移除的模型覆盖会改变选模结果。

文件转换通过既有原子替换、备份和源文件比较机制执行。外部编辑冲突时停止替换并
显示待处理状态；不能覆盖用户的新内容。读取或预览本身不改写文件。
旧 manifest、自定义库、内建 TOML、生成器和模板也须在同一版本中收敛。

已有单一 LLM 配置一次性复制到智能类别；快速类别沿用原键。迁移标记防止后续同步覆盖；
部分失败可重试，保留已经写入的值。两类分别验证推理能力；不支持的类别显示为需要配置。
分类服务选择、账户、凭据与自动开关仍只保留在会话中，不扩大原有凭据留存期限。

## 已实现范围

- 全局快速 / 智能配置和 Keychain 凭据相互独立，设置页提供 OpenAI / DeepSeek / 兼容服务预设。
- workflow v3 仅声明类别；v1/v2、旧自定义库、内建与模板统一迁移。读取不改写文件，保存沿用 CAS 与备份。
- 准入时固定文本、TTS 与润色分类授权，ASR 沿用准入配置快照；请求完成时复核密钥撤销。
- Jev / Clef / Clef Flash 复用同一有类型评分合同，服务/账户变化撤销旧请求与独立用途授权。
- 云 ASR 仅调研：用户选择大陆直连、中文和中英混合优先。建议先实测百炼北京，再与豆包对照；本次未接通音频上传。

定向验证已通过：角色绑定与密钥撤销、推理请求参数、分类端点与 envelope、设置独立性与一次性迁移、workflow v3 迁移与拒绝覆盖。
完整本地 CI 的最终结果见交付记录；不据此宣称真实网络识别效果或物理 macOS 交互通过。

## 实现顺序和验收

1. 定义固定类别、全局绑定和供应商能力校验；统一设置页、保存/恢复及连接验证。
2. 修改 workflow 声明、解析器、schema、内建定义和迁移；移除执行时模型覆盖。
3. 从准入到执行传递模型快照，接通就绪检查、隐私确认、上下文纠错和历史。
4. 更新使用说明，运行 codec/compiler/provider/settings/file-store 的定向测试，
   再执行生成物检查、`just check`、完整 `just ci` 和 diff 检查。

关键行为验证：

- 修改快速类只改变随后使用快速类的运行，智能类和进行中的运行保持原绑定。
- 同一工作流的两个步骤分别使用智能和快速绑定，嵌套分支也正确保留类别。
- 不兼容的类别、未知类别、具体模型覆盖在新格式中有明确诊断。
- 旧格式统一转换且结构不丢失；遇到外部文件修改时保留两边证据并停止替换。
- LLM 设置在录音或执行中途变化时不重定向请求；下一次运行使用新配置。
- 真实目的地与授权一致，撤销授权能阻止后续调用，秘密不进入历史或诊断。
- 缺失智能模型不影响只用 ASR 的输入；下载或启用多个 ASR 模型不产生多个 workflow 类别。
- 原有取消、顺序输出、部分完成、文本 replay 和文件冲突合同继续成立。

自动化检查不能替代设置页的键盘/辅助功能验收或真实录音验证；这些人工验收与真实
云端服务质量实测仍需单独记录。
